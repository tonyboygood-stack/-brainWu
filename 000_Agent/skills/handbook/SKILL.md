# 臨床手冊 — 生成與維護

## 這個 skill 在解決什麼

老吳有 137 張知識卡,但沒有穩定讀書時間,卡建完就沉底被遺忘。他的 vault 裡有**看板**(管理視角:什麼待辦)和 **MOC**(索引視角:有哪些卡),就是沒有**閱讀視角**——一本可以從頭讀到尾的書。

手冊就是那本書。

## 鐵則:手冊是檢視畫面,不是真相來源

這條規則是老吳自己在總框架 MOC 立的:

> **這是檢視畫面,不是真相來源。**維護規則:速查只能從各層濃縮,不新增內容。

所以:
- **卡片是真相來源。** 要改內容去改卡片,不要改手冊清單
- **手冊清單一律由腳本生成**,任何手改都會在下次重生被蓋掉
- **速覽(導讀)寫在 AUTO 標記外面**,重生不會動到

**為什麼一定要自動生成:** 這個 vault 裡每一個靠手動同步的索引都爛掉了——`臨床成長記錄` 承諾的分類索引只填了 18/74,`學習佇列` 停在 checkbox。手冊若靠手動維護,半年後就是第三個。

## 兩本書,同一批卡

| 檔案 | 章 | 小節 | 什麼時候用 |
| :--- | :--- | :--- | :--- |
| `400_Atlas/臨床手冊_推理層次.md` | L0–L5 六層 | MOC 主題 | 想從頭讀,跟著床邊思考順序走 |
| `400_Atlas/臨床手冊_主題查詢.md` | MOC 主題 | L0–L5 六層 | 想查「沉脈怎麼辨」,直接翻脈診那章 |

分章鍵:
- **層次** = `framework` 欄位的第一個 L token(老吳照框架順序寫,最左＝主層)。跨層卡只會出現在主層那一章,不重複
- **主題** = `up` 欄位。一張卡屬於多個 MOC 時,在主題手冊的各章都會出現(那是正確的),但在推理手冊的同一章只出現一次

## 重生

```bash
python 000_Agent/skills/handbook/scripts/build_handbook.py
```

| 參數 | 作用 |
| :--- | :--- |
| (無) | 只換 AUTO 區塊,速覽原樣保留。**平常都用這個** |
| `--check` | 只檢查不寫入,用來驗冪等性 |
| `--fresh` | 整份重建,**會丟掉已寫的速覽**。只在初次建立時用 |

腳本會回報層次分佈、還沒填 `when_to_use` 的張數、沒有 `says` 的卡。

## AI 該做的唯一一件事:提議改寫速覽

腳本只做機械組裝。AI 唯一該動腦的地方是**速覽**——每章開頭那三段:

```markdown
> **這層在幹嘛**：一句話講這層在整個推理裡的角色
> **目前掌握**：2–4 句實質重點（隨卡片累積而長）
> **最容易錯**：一句話，臨床上這層最常犯的錯
```

沿用 note-capture 既有的速覽維護規則,**不是每次重生都改寫**:

1. 某章新增卡片後,**重讀該章速覽**,判斷新卡有沒有帶來速覽該講而沒講的東西
2. 有 → **改寫**速覽(不是往後追加),並更新 `（更新 YYYY-MM-DD）` 日期
3. 沒有 → **不動**,不要為了動而動
4. 速覽**只能寫該章卡片支持得住的內容**,不可自行推論;推論要放進總框架 MOC 的「框架缺口」
5. 保持精簡(至多 6 行)

> ⚠️ 速覽最大的風險是與卡片脫節。每次改寫都要確認它講的東西在該章卡片裡找得到依據。

總框架 MOC 已經有 7 個寫好的速覽(L0、1-2、L4 等),**語氣直接照抄那個口吻**:第二人稱、直白、講完就停。

## `when_to_use` 漸進回填(觸發:「補觸發鍵」)

`when_to_use` 是老吳 2026-07-23 自己加的欄位,寫著「讓知識卡從『知道』進化到『找得回來』」。目前 137 張只有 7 張填了,手冊裡用 **⬜** 標出來。

**這是防遺忘的關鍵欄位,但絕不能一次清完。** 130 張的馬拉松對老吳的體力是災難,做一半就會停,然後這個欄位又變成第四個爛掉的東西。

規則:

1. **一次只挑 3–5 張**,問完就停
2. **優先挑 `clinical_insight` 已經有內容的**——那些他早就想過,最好回答
3. 問法固定一句:「**看到什麼情況/脈象/主訴時,你會想翻出這張卡?**」
4. 一行就好,不要求完整句
5. **AI 絕對不可代筆。** 這欄位的價值在於它是老吳的臨床反射,AI 猜的沒有用。他答不出來就跳過,不要硬湊
6. 填完跑一次重生,⬜ 會自己消失

## 常見錯誤

| 錯誤 | 正確 |
| :--- | :--- |
| 直接編輯手冊的卡片清單 | 去改卡片,然後重生 |
| 每次重生都重寫速覽 | 只有該章卡片有實質變動才提議改寫 |
| 速覽寫了卡片裡沒有的推論 | 只寫卡片支持得住的;推論放框架缺口 |
| 用 `--fresh` 做日常重生 | 平常不加參數;`--fresh` 會丟掉速覽 |
| 一口氣問 130 張 when_to_use | 一次 3–5 張 |
| AI 幫忙寫 when_to_use | 只有老吳能寫 |
| 把手冊當成新知識的存放處 | 手冊是檢視畫面;新知識走 note-capture 建卡 |
