# Question Garden — 問題花園澆水流程

## 這個 skill 在解決什麼

老吳讀書時會冒出問題，丟一張問題卡進 `400_Atlas/Questions/` 就繼續讀（正確，不該打斷閱讀）。但這些問題卡丟進去之後就沒有下一步——目前 33 則問題卡沒有任何一則被系統性地回頭處理過。

澆水就是那個下一步：**老吳出問題，AI 出材料，老吳出觀點。** AI 只負責把庫裡散落各處的相關材料聚攏到問題卡底下，判斷與觀點永遠是老吳的。

## 四個階段

| 階段 | 意思 | 誰動手 |
| :--- | :--- | :--- |
| 🟤 種子 | 問題已捕捉，還沒查 | 老吳丟卡 |
| 🔵 澆水中 | AI 已把相關材料整理進卡裡，等老吳讀 | **這個 skill** |
| 🌸 開花 | 老吳讀完材料，寫下自己的觀點 | 老吳 |
| 🟢 結果 | 觀點已升級成 `400_Atlas/Notes/` 知識卡 | note-capture skill |

看板：`400_Atlas/問題花園.base`

## 澆水流程

### 第零步：選種子

使用者只說「澆水」沒指定哪一則時，**不要自己挑**。讀 `400_Atlas/Questions/`，列出 `階段: 🟤 種子` 的問題卡讓他選，格式：

```
目前有 N 則種子，靜置最久的排前面：

1. [問題卡標題]（靜置 X 天）
   說：{says 欄位內容}
2. ...

要澆哪一則？（可以說編號，或說「最久的那則」）
```

靜置天數用檔案最後修改時間算。優先列靜置最久的——那些是最容易被遺忘的。

### 第一步：讀懂這則問題

完整讀該問題卡：
- `says`：這則問題的一句話核心
- `up`：它掛在哪個 MOC 底下（15/33 則是 `up: []`，沒掛就照內容自己判斷主題）
- `related`：它是從哪張卡或哪個病案長出來的
- 內文的 `## 待釐清的問題` / `## 觸發情境`：真正要回答的東西在這裡

**從這裡抽出 3–6 個搜尋關鍵詞**，包含同義詞與相關的中醫術語（例如問「腎病開闔」，關鍵詞要含 開闔、腎、蛋白尿、肌酐酸、升降、通利）。

### 第二步：四路搜尋

四個來源都要查，缺一不可。每一路都用多個關鍵詞交叉搜，不要只搜標題。

| 路 | 位置 | 找什麼 |
| :--- | :--- | :--- |
| 1 | `400_Atlas/Notes/`（138 張） | 老吳自己已經想過的東西——**最重要**，避免重複造輪子 |
| 2 | `400_Atlas/Library/wiki/`（1175 頁） | 文獻怎麼說。每一筆都要標 `醫家` |
| 3 | `400_Atlas/Case/`（22 則） | 老吳自己的病人身上有沒有出現過 |
| 4 | `500_Inbox/`（暫存區＋散檔） | 讀過但還沒整理的原始素材 |

**文獻庫的醫家透鏡規則**（沿用 library-ingest）：引用 wiki 頁時必須標出 `醫家:` 欄位的值。不同醫家的說法要分開列，不可混成一段「中醫認為」。

### 第三步：寫入澆水記錄

在問題卡**末尾**追加（不要動既有內容、不要改 frontmatter 既有欄位）：

```markdown
## 🚿 澆水記錄 YYYY-MM-DD

### 庫裡已有的（你自己想過的）
- [[卡片名]] — 這張卡回答了問題的哪一部分／哪一部分沒回答

### 文獻怎麼說
- [[wiki頁名]]（醫家：趙紹琴）— 一兩句重點
- [[wiki頁名]]（醫家：李辛）— 一兩句重點

### 你自己病案裡的線索
- [[病案名]] — 這個病人身上出現過什麼相關的東西

### 未整理的素材
- `500_Inbox/xxx.md` — 有相關但還沒整理成卡

### 🔴 庫裡沒有的
- （背景知識，不是文獻結論，僅供參考方向）

### 這一輪還沒解決的
- 材料湊齊之後，原問題還缺什麼才能回答
```

**沒找到就寫沒找到。** 任何一個區塊空的就直接寫「庫裡沒有」，不要為了填滿而拉不相關的東西進來。

### 第四步：翻階段

frontmatter 的 `階段` 改成 `🔵 澆水中`。其他欄位（`up`/`collection`/`related`/`created`/`says`/`tags`）一律不動。

搜到的材料如果和這則問題強相關，可以補進 `related`（雙向：對方那張卡也要補回連結，遵守 note-capture 的雙向連結規則）。

### 第五步：回報

對話裡只給摘要，不要把整段澆水記錄貼出來浪費 context：

```
已澆水：[問題卡名]
找到 N 筆：知識卡 a 張、文獻 b 頁（醫家：…）、病案 c 則、未整理素材 d 筆
🔴 庫裡沒有的：…
階段已翻成 🔵 澆水中

這一輪的材料還缺什麼：…
```

## 開花與結果（老吳動手，AI 配合）

**開花**：老吳讀完澆水記錄，在問題卡寫下自己的觀點。這時把 `階段` 翻成 `🌸 開花`。

**結果**：說「這則可以成卡了」→ 交給 `note-capture` skill 走完整流程（重疊檢查、collection、up、related、says、框架解構、clinical_insight），存進 `400_Atlas/Notes/`。存好之後：
- 問題卡 `階段` 翻成 `🟢 結果`
- 問題卡 `related` 補上新知識卡的連結
- 新知識卡 `related` 補回這則問題卡

---

## 證據誠實規則（不可違反）

沿用 library-ingest 的既有規範，不另立一套：

1. **只用庫裡實際存在的內容作答，每一筆都標來源檔名**
2. **庫裡沒有就直說「庫裡沒有」**，不要用背景知識填空再假裝是查到的
3. **背景知識必須標 🔴**，而且不可當成文獻結論陳述
4. **引用文獻頁必須標 `醫家`**，不同醫家的說法分開列
5. **不要替老吳下判斷**。澆水是把材料攤開，不是給答案。看到 AI 忍不住想寫「所以應該是 X」的時候，改寫成「這幾筆材料指向 X，但庫裡沒有直接講到 Y」

## 常見錯誤

| 錯誤 | 正確 |
| :--- | :--- |
| 只搜問題卡標題的字面 | 抽 3–6 個關鍵詞含同義詞與相關術語交叉搜 |
| 四路只搜了 Notes 和 wiki | 病案和 Inbox 也要搜——老吳自己的病人和沒整理的素材常常才是關鍵 |
| 引用 wiki 頁沒標醫家 | 每筆都標，不同醫家分開列 |
| 為了填滿版面塞不相關的連結 | 空的區塊就寫「庫裡沒有」 |
| 直接給問題的答案 | 只攤開材料，判斷留給老吳 |
| 改動 frontmatter 既有欄位 | 只加 `階段` 和（必要時）`related` |
| 把整段澆水記錄貼進對話 | 寫進檔案，對話只給摘要 |
