# 今日焦點推薦與確認

## 目的

「早安」不是自動排程，而是把分散的期限、專案與交接事項收斂成有限候選，讓老吳確認後才成為今日承諾。

## 候選來源

依序檢查下列來源；未確認前不可修改其中任何一個檔案：

1. `100_Todo/今日要事.md`：只有其 `date` 是今天時，保留未完成的已確認事項。
2. 當天的固定事項，例如 `100_Todo/每周一_王家小館阿姨看診.md`。
3. 昨日日記 `300_Journal/YYYY-MM/YYYY-MM-DD.md` 的 `## 明天待辦`，及其中明確可在今天落地的具體改善行動。
4. 當週 `100_Todo/YYYY-WNN_本週代辦.md`。只有檔案週次與今天相符時才可使用；沒有本週檔案時，不得拿舊週未完成事項冒充本週任務。
5. `600_Projects/*/tasks/*.md` 中 `status: 🔴 待辦` 或 `status: 🟡 進行中` 的任務。依 `目標`、`時間`、`優先度` 與是否阻塞里程碑判斷。

`時間: 未分類`、等待外部觸發、尚未到期的例行任務，不能只因未完成就被推薦。`400_Atlas/Questions/`、學習佇列與 `#靈感發想` 不自動成為今日任務；`#行動與待辦` 僅回報收件匣數量，除非老吳明確選擇，否則不升格。

## 排序與回覆

依序優先：今天固定或明確到期、七日內期限、診所關鍵路徑／高優先度本月任務、昨日交接、當週高槓桿下一步。合併本質相同的任務。

提出最多 3 個「今日建議」與 2 個備選；每一項標示來源與一行理由。若日期矛盾、來源過時或資料不足，要直接說明。

```markdown
━━ 今日建議（請確認）━━
1. [ ] 任務 — 為何是今天｜來源：[[原始任務]]
2. [ ] 任務 — 為何是今天｜來源：[[原始任務]]
3. [ ] 任務 — 為何是今天｜來源：[[原始任務]]

備選：...

回覆「確認 1、2、3」、「1 換成備選 A」，或直接說你今天想做什麼即可。
```

在完整早安中，先完成所有指定資訊區塊，再於輸出末尾提出建議並等待確認。確認前不得寫入「今日要事」，但不得因等待確認而省略完整早安的其他區塊。快速早安則依主流程的精簡規則執行。

## 確認後的唯一寫入

只在老吳明確確認、替換或指定今日焦點後，更新 `100_Todo/今日要事.md`：

- `date` 寫今天，`status` 改為 `已確認`。
- 「今日三件事」最多 3 項，每項包含原始任務連結與一行理由。
- 未選項目在「今日備選」呈現，不能偽裝成承諾。
- 不更改原始任務、週代辦或專案任務的完成狀態。
- 若今天已確認過，先問「保留、替換或追加」，不可靜默覆蓋。
