## 二、兩種視角的版面（老吳提的電腦 vs 手機）

**核心差異：手機回答「我現在要做什麼」，電腦回答「診所現在怎麼樣」。**

### 📱 手機（員工工作中隨手看）— 單欄，由上而下

```
┌──────────────────────┐
│ 1  我的今日任務（未完成優先）  │  ← 最重要，第一眼
│ 2  ⚠️ 待處理異常（🔴 置頂）   │
│ 3  📢 老闆公告（有新的才顯示） │
│ 4  💬 備註流                │
│ 5  ✍️ 每日一句 ＋ 🌾 節氣     │
│ 6  📖 昨日診所日誌（收合）    │
└──────────────────────┘
```

> 手機版**不放**「今日任務狀態全景」——她只需要知道自己的，不需要知道全局。

### 🖥️ 電腦（櫃台常駐螢幕／診間平板）— 三欄全景

```
┌────────────┬──────────────┬────────────┐
│ 今日任務狀態  │   備註流（主）    │  📢 老闆公告  │
│ （全區）     │                │  ✍️ 每日一句  │
│            │                │  🌾 節氣      │
│ ⚠️ 待處理   │                │  🌳 平衡木入口 │
├────────────┴──────────────┴────────────┤
│  📖 今日診所日誌（收診後出現，橫幅大字）           │
└──────────────────────────────────────┘
```

> 每日日誌放在電腦版底部橫幅，是因為**它是收診時的儀式**——關機前最後看的東西。

## 三、⭐ 節氣與節慶板塊（自動化，且最符合診所調性）

老吳舉的例子是「端午節快到囉」。這件事完全可以自動化，而且**對中醫診所來說，比一般公司有意義得多**——因為節氣本來就是中醫的語言。

| 類型 | 提前幾天 | 顯示什麼 |
|---|---|---|
| **二十四節氣** | 3 天 | 「下週三立冬」＋ 一句該節氣的養生提示 |
| 傳統節慶 | 7 天 | 「端午節快到囉」＋ 診所要準備什麼（艾草？香包？） |
| 國定假日 | 14 天 | 提前提醒排班與公休公告 |
| 診所紀念日 | 7 天 | 開幕週年、夥伴到職週年 |

**三個延伸價值：**

1. **接衛教**：立冬那天，候診區電視自動播冬季進補的衛教內容；節氣提示也可以印在藥袋上
2. **接任務**：節氣自動觸發季節性任務（換季深度清潔、空調濾網、艾灸用量調整）
3. **接品牌**：這是低成本但很有記憶點的東西——病人會記得「那家中醫每次節氣都會提醒我」

> 資料來源：農曆與節氣表是公開資料，可以直接內建一份未來十年的靜態表，**不需要任何 API、不需要網路**。成本近零。

## 三之二、⭐⭐ 今日播報：天氣 ＋ 節氣 ＋ 一句可以跟病人說的話

> 2026-09-08 老吳：「可以提醒在布告欄包含天氣（包含一句溫暖的提醒，例如：記得提醒病人明天要轉冷，多穿件衣服喔！）之類，讓櫃台也有資訊可以傳達，**這也能讓助理收穫醫療人員的付出感**。」

**這是整份企劃裡我認為對「留人」最有效的一個功能，而且成本極低。**

### 為什麼

櫃台助理的工作內容是掛號、結帳、包藥、清潔——**全都是行政與勞務，沒有一項會讓她覺得自己在照顧人**。這是小診所離職率的真正來源：不是薪水，是「我做的事沒有意義」。

給她一句每天不一樣的、專業的、可以主動說出口的話，她就從「收錢的」變成「照顧人的」。**這一句話不花錢，但它改變的是她對自己工作的定義。**

> 八角框架上，這是**驅動力 1（重大使命與召喚）在櫃台的具體化**——而且是唯一能在櫃台實現的。

### 板塊長什麼樣

```
┌─────────────────────────────────┐
│  🌤️ 今日播報　　　　　9/8（一）處暑     │
│                                  │
│  今天 31°C／26°C，午後有雷陣雨       │
│  明天下探 22°C，日夜溫差大           │
│                                  │
│  ── 今天可以跟病人說 ──              │
│  「明天會轉涼十度左右，離開前記得       │
│   提醒他們帶件外套，尤其是剛做完       │
│   針灸、毛孔還開著的時候。」           │
│                              [已讀] │
└─────────────────────────────────┘
```

### 內容從哪來

| 素材 | 來源 |
|---|---|
| 今日／明日天氣 | 中央氣象署開放資料 API（免費、公開） |
| 節氣、節慶 | 內建靜態表 |
| **那一句話** | AI 依「天氣 ＋ 節氣 ＋ 診所當日狀況」產出草稿，**老吳可審可改可預先寫** |

### 一句話的四種類型（讓它不會每天都一樣）

| 類型 | 範例 |
|---|---|
| **天氣提醒** | 「明天下探 22 度，記得提醒病人帶外套——尤其剛針完毛孔還開著。」 |
| **節氣養生** | 「今天立冬。可以跟病人聊一句：立冬進補不是急著吃補，是先把睡眠補回來。」 |
| **診所實務** | 「下雨天地板滑，提醒長輩進門慢一點。」 |
| **溫度提醒** | 「今天很忙。如果看到有人等超過三十分鐘，走過去說一聲就好，不用解釋原因。」 |

> **第四類最重要。** 它教的不是知識，是待人的方式——而那正是「服務品質」真正的內容。

### ⚠️ 一個界線

這句話是**衛教與關懷的提示**，不是診斷或醫囑。措辭一律停在生活建議層級（多穿衣、慢一點、早點睡），**不涉及病症判斷或用藥建議**。AI 草擬 → **老吳審過才發**，這條不能省。

### 延伸：這句話也是助理的專業成長軌跡

每天一句累積下來，一年就是 300 句中醫生活衛教。
- 可以做成她的「衛教語錄」收藏，掛在角色卡上
- 累積說出口 N 次 → 解鎖稱號（例如「衛教員」→「暖心傳聲筒」）
- **這是「技能晉升加給」之外，第三條看得見的專業成長路徑**

## 四、~~心情留言板~~ → **不做**（2026-09-08 老吳決定）

心情留言板取消。它原本要承擔的功能，由兩個更好的東西取代：

| 原本要做的事 | 改由誰做 |
|---|---|
| 讓員工留下當天的痕跡 | **「今天值得記一筆」按鈕**（見 [[600_Projects/平衡木診所遊戲化系統/企劃書/05_平衡木編年史\|05]]）——門檻更低、當天就看得到成果 |
| 提供每日日誌的溫度素材 | 同上 |

> 這個取捨是對的。心情板有個結構性問題：只有 1–2 位員工，老闆看得到就等於沒有匿名，寫出來的永遠是修飾過的版本。
> 「今天值得記一筆」沒有這個問題——因為它問的不是「你今天心情如何」，而是「今天有什麼有趣的事」。**對外的觀察沒有心防，對內的自陳有。**

## 五、⭐ AI 每日診所日誌

### 觸發與資料

**觸發**：當天最後一個「收診結束」任務被完成的那一刻。

**輸入**（全部是系統內已有的資料）：

| 來源 | 內容 |
|---|---|
| 排班表 | 誰在班、守備哪區 |
| 任務紀錄 | 完成了哪些、幾點完成 |
| 備註 | 當天新增的，尤其 🔴 |
| 感謝卡 | 今天有沒有人收到 |
| 成長系統 | 升階、稱號解鎖 |
| 心情留言板 | 狀態表情與那句話 |
| 平衡木 | 今天有沒有里程碑 |
| 節氣表 | 今天是什麼日子 |
| 天氣（選配） | 免費 API，成本近零但畫面感加很多 |

**輸出**：3–6 句有畫面感的敘事。

### 語氣：老吳後台可切換（這是你的第三個創意空間）

同一天的資料，四種寫法：

**① 溫暖散文（建議預設）**
> 今天下午三點多，雨忽然大起來。○○○ 把傘桶往門邊挪了挪，後來進來的六個人都沒把地板弄濕。收診前她在備註寫了一句「傘桶要再買一個」。
> 今天完成了 11 項任務，第 47 位客人走進了這扇門。

**② 武俠風**
> 　雨勢驟急。櫃台一役，○○○ 獨守三時辰，來客十七人，未有一人久候。
> 　酉時三刻，藥香未散，包藥七帖，皆按時交付。
> 　是日無事。無事，便是最好的一日。

**③ RPG 旁白**
> 　【第 47 日】
> 　○○○ 守備【櫃台】【調劑室】，遭遇來客 ×17，全數順利應對。
> 　完成任務 11 項　│　獲得金幣 ×85
> 　⚠️ 發現異常：候診區傘桶容量不足（已登記）
> 　🌧️ 天候：大雨　│　士氣：良好

**④ 日式療癒**
> 　雨的日子。
> 　傘靠在門邊，滴著水。
> 　藥香比平常濃一些，大概是濕氣。
> 　十七個人來過，都回去了。
> 　明天見。

> **建議做法：預設①，讓老吳隨時切換，並保留一個「隨機」選項。**
> 隨機出現不同語氣，就是八角框架驅動力 7（未知與好奇）最輕量、最無害的用法——每天下班前有一點小期待，但沒有任何焦慮。

### 老吳定的驗收標準（2026-09-08）

> **「我需要的是一點期待、一點畫面、一點收尾、一點溫度。」**

這四個「一點」就是每日日誌的規格書。四個都要有，而且都只要「一點」——過頭就變成矯情。

| 要素 | 怎麼做到 |
|---|---|
| **一點期待** | 語氣可隨機、偶爾出現稀有句型、明天的節氣或天氣預告放在結尾 |
| **一點畫面** | 寫具體的動作與物件（傘桶、雨聲、藥香），不寫抽象形容 |
| **一點收尾** | 最後一句是收束，不是待辦。「明天見。」勝過「還有三項未完成」 |
| **一點溫度** | 素材來自「今天值得記一筆」的投稿 ＋ 老吳可補的那一句 |

### 三條寫作規則（要寫進 AI 的指令裡）

| 規則 | 為什麼 |
|---|---|
| **只寫事實，不評價人** | 「○○○ 完成了 11 項任務」可以；「○○○ 今天很認真」不行。一旦 AI 開始評價，日誌就變成考績表，員工會開始表演給它看 |
| **不寫沒做完的事** | 沒完成的任務屬於明天的待辦，不屬於今天的故事。日誌是收尾，不是檢討 |
| **可以寫氛圍與群像，不可寫可識別的個人** | 見下方修正 |

> 第一條最重要。**AI 一旦開始誇獎，誇獎就變得廉價；一旦開始批評，這個功能就死了。**
> 它的工作是**記錄**，不是評分。感情來自事實本身——「後來進來的六個人都沒把地板弄濕」比「○○○ 很細心」動人一百倍。

#### 第三條的修正（2026-09-08 老吳提問：「病人帶著微笑離開」可以嗎？）

**可以。** 原本寫「不碰病人任何細節」太嚴了，會讓日誌少掉最重要的溫度來源。正確的界線是**「可不可識別」**，不是「有沒有提到病人」：

| ✅ 可以寫 | ❌ 不可以寫 |
|---|---|
| 「有位病人帶著微笑離開」 | 「王小姐的五十肩好多了」 |
| 「今天有人帶了自己種的芭樂來」 | 「三號床那位七十幾歲的張伯伯」 |
| 「十七個人來過，都回去了」 | 任何姓名、年齡＋性別＋病症的組合 |
| 「有個孩子在候診區睡著了」 | 病名、處方、療程進度 |

**判準：把這段文字給一個陌生人看，他能不能指認出是誰。** 不能，就可以寫。

> 這條界線同時守住兩件事：日誌保有人的溫度，而系統仍然不儲存任何可識別的病人資料。

### 老吳可以加一句話

日誌產生後，老吳可以在底下**補一句自己的話**（選填）。
系統產的是事實，你補的是溫度。這一句話的份量，比整篇 AI 文字加起來都重。

### 每日日誌會沉澱成什麼

- **每週**：自動彙整成週報（給老吳看營運，不公開）
- **每月**：月底小結，回顧這個月的故事
- **每年**：候選成為[[600_Projects/平衡木診所遊戲化系統/企劃書/05_平衡木編年史|平衡木]]的里程碑素材，或集結成「平衡木年鑑」

## 六、每日一句：格言／座右銘（2026-09-08 老吳定義）

> 老吳：「今日一句話是指像是格言或座右銘那種，一個正向溫暖的提醒。」

**定位**：這是給**員工**看的（不是給病人的），一天一句正向溫暖的提醒，開機時第一眼看到。

### 四個來源，建議混用

| # | 來源 | 說明 | 版權 | 期別 |
|---|---|---|---|---|
| **①** | **中醫典籍** ⭐ | 《黃帝內經》《千金要方》等古籍句子。**已進入公共領域，可自由使用** | ✅ 安全 | 第 1 期 |
| **②** | **台灣／中文諺語** | 民間諺語、俗諺，無著作權人 | ✅ 安全 | 第 1 期 |
| **③** | **老吳自己寫的** ⭐⭐ | 從 `400_Atlas/Notes/` 抽你自己寫過的句子 | ✅ 你的 | 第 2 期 |
| ④ | 現代作家格言 | ⚠️ **要小心**：現代作品仍在著作權期內，商業場所公開展示有風險 | ⚠️ 避免 | ❌ |

### 為什麼推薦①中醫典籍

- **完全沒有版權問題**（作者過世逾五十年，已入公共領域）
- **與診所調性完全吻合**——一間中醫診所每天引一句《內經》，這本身就是識別
- 句子本來就短、有節奏、適合當每日一句
- 可以配合節氣（春三月的句子在春天出現）

範例（示意，實際選句由老吳定）：
> 「上工治未病。」
> 「恬惔虛無，真氣從之。」
> 「春三月，此謂發陳。夜臥早起，廣步於庭。」

### 為什麼③最有價值（第 2 期）
