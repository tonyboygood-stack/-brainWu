# 05 平衡木：診所編年史

> 2026-09-07 老吳定案：里程碑牆改成**候診區最大的那棵樹**，就是「平衡木」本身。
> 隨時可以點開瀏覽，樹上留下診所的編年史。

---

## 一、為什麼這個改動比原本的「里程碑牆」好很多

| | 里程碑牆 | **平衡木（樹）** |
|---|---|---|
| 隱喻 | 陳列、展示 | **生長** |
| 情感 | 看紀錄 | **看它長大** |
| 品牌 | 無關 | **診所就叫平衡木** |
| 現實對應 | 沒有 | **候診區真的有那棵樹** |

**最關鍵的差別：樹會長大。** 牆只是越掛越滿，樹是**隨著診所的成長而變化**——這讓「診所的歷史」不是一份檔案，而是一個活著的東西。

而且它有現實錨點：候診區那棵真的樹，跟系統裡的樹是同一棵。病人在候診區看著它，員工在系統裡也看著它。

---

## 二、視覺設計

### 里程碑 ＝ 掛在樹枝上的木牌

不用果實、不用年輪，用**掛牌**。理由：

- 符合設計簡報定的**日式簡約 · 自然材質**風格（木牌、麻繩）
- 可以點開、可以留言，互動性最好
- 視覺上豐富但不吵——牌子隨風輕輕晃動就夠了
- 呼應日本神社繪馬／台灣廟宇祈願牌的文化記憶，「掛上去」這個動作本身就有儀式感

### 樹會隨著里程碑增加而長大

| 階段 | 樹的樣子 |
|---|---|
| 開幕 | 小樹苗，一兩片葉 |
| 第一年 | 有樹幹、幾根枝、掛著十幾塊牌 |
| 第三年 | 枝葉茂密，牌子成串 |
| 第五年 | 大樹，樹下開始有東西（見下） |

> **成長的觸發不用複雜**：里程碑數量、開業月數、任務累積完成數，三者取一或加權都行。第 1 期用「開業月數」最單純。

### 樹的分層（可選，第 2 期）

- **樹梢**：最新的里程碑（一眼看到最近發生什麼）
- **樹枝**：依年份分枝，一年一枝
- **樹根**：籌備期的故事（簽租約、裝修、面試第一位夥伴）——**診所在開幕前就已經有歷史了**
- **樹下**：離開的夥伴留下的傳承日誌，像落葉化成土

> 「樹根＝籌備期」這一層我特別推薦。你從 2026 年 5 月就開始丈量、找設計師、談租約，那些都是診所的一部分。開幕不是第一天，只是樹冒出土的那天。

## 三、里程碑條目的結構

點開一塊木牌，看到：

```
─────────────────────────────
🏛️  2026-10-25　診所開幕
─────────────────────────────

  「早上八點，鐵捲門拉開的聲音特別響。
   第一件事不是開機，是把候診區那盆樹
   往窗邊挪了半公尺——它需要更多光。」

  在場：老吳 · ○○○

  ── 心情留言（3）──
  ○○○ 2026-10-25：緊張到手在抖，但門開的那一刻好像就沒事了
  老吳 2026-10-25：謝謝你陪我開這扇門
  △△△ 2028-03-14：我 2028 年才來，但每次看到這則都很感動 🌱
─────────────────────────────
```

### 四個組成部分

| 部分 | 誰產生 | 說明 |
|---|---|---|
| **標題與日期** | 系統自動 or 手動標記 | 見下方里程碑清單 |
| **小故事** | **AI 草擬 → 老吳潤稿** | 有畫面感的三五句話。詳見 [[600_Projects/平衡木診所遊戲化系統/企劃書/07_AI背景層\|07 AI 背景層]] |
| **參與者** | 系統自動（讀排班表） | 那天誰在班 |
| **打卡與心情留言** | 參與者 ＋ **後來的瀏覽者** | 見下 |

### ⭐ 打卡與留言：**後來的人也能留言**，這是最重要的設計

老吳原話是「參與者與瀏覽參觀者打卡與心情留言」——**「瀏覽參觀者」這三個字是整個設計的關鍵。**

它讓編年史從博物館變成活的東西：

- 2028 年才到職的新人，可以在 2026 年開幕那則底下留言
- 她沒有參與，但她**接上了**
- 對當年在場的人來說，兩年後有人來留言，那份工作的意義被重新確認了一次

> 這一條直接打中八角框架的**驅動力 1（重大使命與召喚）**，而且是最深的那一層：不是「我做了什麼」，是「我屬於一個比我更長的東西」。

**留言要不要限制？** 建議：不限制、不可刪（只能補），與任務備註同樣的「只增不刪」原則。因為這是歷史。

## 四、里程碑清單（老吳可增刪，這是討論用的初稿）

分成六類。**A、B、C 由系統自動偵測；D、E、F 需要人手動標記。**

### A. 開業里程碑（一次性，永不再現）⭐ 最珍貴

| 圖示 | 里程碑 | 觸發 |
|---|---|---|
| 🌱 | 簽下租約 | 手動（樹根層，回溯補登） |
| 🔨 | 裝修動工 | 手動（樹根層） |
| 🤝 | 第一位夥伴簽約 | 手動（樹根層） |
| 🏛️ | **診所開幕** | 手動 |
| 🥇 | 第一位病人 | 自動 |
| 💊 | 第一張處方 | 自動 |
| 🪡 | 第一次針灸 | 自動 |
| 💌 | 第一封病人感謝 | 自動（接 04） |
| 🌿 | 第一本傳承日誌 | 自動（接 02） |
| 💡 | 第一個被採納的提案 | 自動（接 03） |
| 💰 | **第一次單月損益兩平** | 手動 ← 對你意義最大的一則 |
| 🔁 | 第一位回診滿 10 次的病人 | 自動 |

### B. 數量里程碑（累積）

第 100 / 500 / 1,000 / 5,000 位病人 · 第 1,000 次針灸 · 第 100 次滿診 · 累積完成 1,000 個任務

> ⚠️ 建議**間隔要拉開**。里程碑太密就不叫里程碑了，會變成通知噪音。

### C. 時間里程碑

開業滿月 · 滿百日 · 滿一年 · 滿三年 · 滿五年 · 每年的開幕紀念日

### D. 人的里程碑 ⭐ 這一類最有溫度

| 里程碑 | 說明 |
|---|---|
| 新夥伴加入 | 到職日 |
| 夥伴第一次升階 | 接 01 的位階系統 |
| 夥伴滿一年 / 滿兩年 | 對齊年資調薪節點 |
| **夥伴的最後一天** | ⭐ 見下 |

> **「夥伴的最後一天」一定要做，而且要做得溫暖。**
> 離職在多數公司是被抹掉的事——帳號停用、名字消失。但在這裡，她的那則會永遠掛在樹上，她的傳承日誌會留在樹下。
> 這件事有兩個效果：對走的人，這是體面的告別；**對留下的人，這是「在這裡工作的痕跡不會被刪掉」的證明**。
> PT 流動性高，這一條的價值反而更大。

### E. 意外里程碑（最有故事性）⭐

颱風天照常看診 · 停電了還是看完 · 第一次有病人送禮 · 第一次有病人帶家人來 · 單日病人數破紀錄 · 診所第一次公休出遊 · 招牌燈第一次壞掉

> 這一類**不可能自動偵測**，需要人當下標記。所以要有一個功能——

#### 「今天值得記一筆」按鈕 ⭐⭐

**主畫面上一個常駐的按鈕，任何人隨時可以按。**

按下去 → 寫一句話 → 進入老吳的候選箱 → 老吳決定要不要掛上樹。

這個按鈕的價值：
- E 類里程碑只能靠現場的人捕捉，系統再聰明也偵測不到「今天有位阿姨帶自己種的芭樂來」
- **它讓員工成為診所歷史的作者，而不只是紀錄裡的人名**
- 成本極低：一個按鈕、一張表、老吳按個核可

### F. 老吳的個人里程碑（可選）

女兒第一次來診所 · 第一次準時六點下班 · ……

> 放不放你決定。放了會讓這棵樹更像一個人的故事，而不只是一間店的財報。

## 五、資料模型

| 資料表 | 說明 |
|---|---|
| `milestones` | id、日期、類型（A–F）、圖示、標題、**小故事文字**、`層`（樹根／樹枝／樹梢）、狀態（候選／已掛上）、建立方式（自動／手動） |
| `milestone_participants` | milestone_id、staff_id（系統從排班表自動帶入，可手動增修） |
| `milestone_comments` | milestone_id、留言者、內容、時間、`是否為當年參與者`（用來在 UI 上區分「當時的人」與「後來的人」） |
| `milestone_candidates` | 「今天值得記一筆」的投稿：投稿人、內容、時間、老吳處理狀態 |
