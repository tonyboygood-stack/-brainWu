**關聯專案：** [[600_Projects/東湖診所開業計畫/index|東湖診所開業計畫]]

## 一句話定位

把診所日常的瑣碎工作（澆花、下診整理、包藥、消毒…）變成一張「診所平面圖上的任務地圖」，員工用角色認領並完成任務，系統自動留下**誰、什麼時候、做了什麼、留了什麼交接備註**的完整紀錄，累積的經驗值同時是**資歷證明**與**獎金依據**。

### 明確不做的事（避免與既有系統重疊）

| 功能 | 由誰負責 |
|------|---------|
| 掛號、病歷、健保申報、收費 | **百會電腦**（已列入採購） |
| 看診輔助、病歷摘要 | clinic-ai-assistant（獨立 repo） |
| 員工任務、交接、經驗值、代入感 | **← 本專案** |

> 本系統不碰任何病人個資，只處理「員工 × 任務 × 時間」三種資料。這個邊界要從第一天守住，資料才單純、法規風險才低。

## 為什麼值得做（以及誠實的風險）

### 依實際編制（1 FT + 1 PT，未來 2 FT + 2 PT）的真實價值

初期只有 2 位員工，所以這套系統的價值**不在「管理很多人」**，而在四件事：

1. **交接不漏接** — 週三 PT 獨自值班、週六雙人班，交接訊息（「第二盆快枯了」「艾灸排煙異音」）若只靠口頭或 LINE 會被洗掉。任務備註綁在「地點＋任務」上，下一個人打開就看見。
2. **資歷有據可查** — 現有獎金制度已有「久任」「技能晉升加給」「服務品質獎金」，但目前沒有客觀依據。任務紀錄讓加薪與晉升**有數字可談**，對雙方都公平。
3. **瑣事有回饋感** — 清潔消毒、澆花這類沒有成就感的工作，是小診所離職率的隱形殺手。遊戲化的目的不是監控，是讓「做完了」這件事被看見。
4. **SOP 自然沉澱** — 呼應 [[600_Projects/東湖診所開業計畫/人員招募/老闆的自我修養|老闆的自我修養]] 裡「共創 SOP 的遊戲化」：任務清單本身跑久了就是診所的 SOP，不用另外寫。

### 誠實的風險（三個要先想清楚的）

- **⚠️ 開幕期不要蓋系統。** 你自己寫過「剛開業時不需要完美的數位系統」，這句話是對的。10/25 開幕前後最忙，此時投入開發會兩頭燒，而且那時你根本還不知道真正的任務清單長什麼樣。**建議先跑第 0 期（見下方分期）。**
- **⚠️ 遊戲化很容易變成監控。** 2 個人的診所，如果系統變成「老闆在看你有沒有偷懶」，會直接反效果。設計原則：**只記正向、不做懲罰性排名、備註對事不對人**、員工看得到自己的完整紀錄（不是黑箱）。
- **⚠️ 不要當成法定出勤憑證。** 勞基法要求的出勤紀錄需保存 5 年，若系統故障或員工忘記點，會變成勞資爭議。**正式差勤仍用打卡鐘或雲端差勤系統**，本系統的時間戳定位為「任務完成軌跡」，是輔助不是法定憑證。

## 系統模型（把粗略想法整理成五層）

| 層 | 內容 | 說明 |
|----|------|------|
| **地圖層** | 診所平面圖 + 可點擊分區 | 植物區、診療區 1/2/3、櫃檯、藥局/包藥區、消毒區、候診區、廁所 |
| **角色層** | 員工角色卡 | 頭像、暱稱、等級、目前解鎖的技能、到職天數 |
| **任務層** | 任務模板 → 任務實例 | 模板 =「每天早上澆花」；實例 = 今天那一筆，有狀態/認領人/時間/備註 |
| **記錄層** | 不可竄改的完成日誌 | = 交接留言板 = 資歷軌跡（只能補註，不能刪改） |
| **成長層** | XP / 等級 / 技能解鎖 | 對應現有獎金制度，不另造一套平行貨幣 |

### 使用者實際流程

**員工端（手機）**
1. 早上到診所 → 打開網頁（已加到主畫面）→ 看到診所平面圖，植物區上面浮著一個💧圖示
2. 點💧 →「澆花（每日）／+10 XP」→ 點「我完成了」
3. 選填備註：「第二盆看起來快枯掉了，可能要換位置」→ 送出
4. 圖示消失，角色頭上跳 +10 XP，經驗條前進

**老吳端（電腦／診間平板）**
- 平面圖總覽：哪些區還有未完成任務，一眼看完
- 交接牆：所有備註依時間排列，可篩選分區
- 月結報表：每位員工的完成數、技能解鎖狀態、可匯出 CSV 給獎金計算用

## 資料模型草案（五張表）

| 資料表 | 主要欄位 |
|--------|---------|
| `staff` | id、姓名、暱稱、頭像、職務（FT/PT/醫師）、到職日、累積XP、等級、已解鎖技能 |
| `zones` | id、名稱、平面圖座標(x,y)、圖示 |
| `task_templates` | id、zone_id、任務名稱、週期規則（每日／每週／每次下診／臨時）、XP值、圖示、SOP說明 |
| `task_instances` | id、template_id、狀態、應完成時間、**完成者**、**完成時間**、**備註**、照片(選配)、建立時間 |
| `xp_log` | staff_id、task_instance_id、獲得XP、時間、原因 |

> `task_instances` 這張表就是整個系統的核心資產：它同時是打卡紀錄、交接留言板、與獎金計算的原始憑證。設計上**只允許新增，不允許刪除或修改**（要更正就新增一筆補註），這樣紀錄才有公信力。
>
> 另外建議 `zones` 與 `staff` 都預留 `clinic_id` 欄位——現在只有一家店，加這個欄位成本是零，未來若展店不用重寫資料庫。

## 技術路線建議

### 推薦：網頁 App（PWA）

| 層 | 選用 | 理由 |
|----|------|------|
| 前端 | React + Tailwind | 生態成熟、AI 協作寫起來最順 |
| 地圖 | **靜態平面美術圖 + 可點擊熱區**（非遊戲引擎） | 這不是動作遊戲，不需要物理引擎與即時運算；用一張好看的 2.5D 俯視圖疊上互動熱區，成本 1/10、效果 8 成 |
| 角色動態 | CSS 動畫或 Pixi.js（第二期再加） | 角色走動、完成任務的粒子效果等「代入感」可後補 |
| 後端 | **Supabase**（Postgres + 登入 + 即時同步 + 檔案儲存） | 免自架、免費層綽綽有餘、內建帳號系統，手機完成任務時診間螢幕即時更新 |
| 部署 | Vercel 免費層 + PWA「加到主畫面」 | 免上架、免審核、改版即時生效，不用叫員工更新 App |

### 為什麼不用 Unity / Godot 做原生 App

| 路線 | 優點 | 缺點 | 判斷 |
|------|------|------|------|
| **網頁 PWA** | 手機電腦都開得了、免上架、改版即時、幾乎零月費 | 動畫細膩度不如原生 | ⭐ **推薦** |
| Godot / Unity 原生 App | 畫面與動畫最完整 | 需上架 App Store／Google Play、需工程師、每次改動要重新發版、雙平台維護 | ❌ 無工程師、預算有限，不划算 |
| 現成工具（Notion／Trello／Habitica） | 幾乎零開發 | 沒有診所平面圖、沒有代入感、資料不好客製 | ✅ **適合當第 0 期過渡** |

### 美術素材怎麼來（成本最低路線）

- **診所平面圖：直接沿用成舍設計的 3D 建模示意圖**，找一張俯視角度的，加工成遊戲風格底圖——這是現成資產，不用重畫。
- **角色頭像／立繪：** AI 圖像生成，做 5–8 種可選外觀（髮型／制服顏色）讓員工自選，就有代入感，不需要客製美術。
- **任務圖示：** 用免費圖示庫（Lucide、Phosphor）或 emoji，第一期不必花錢。

## 分期開發範圍

### 第 0 期：開幕前後 1–3 個月（**不寫任何程式**）

用最低成本方式跑真實流程，目的是**把任務清單養出來**：
- 用 Obsidian Base 看板（診所已在用）或一塊實體白板，列出每日／每週例行工作
- 每天勾選、寫備註，跑 1–3 個月
- 產出：一份真實的任務清單 + 真實的痛點清單 → 這份清單就是第 1 期的 `task_templates` 內容

> 這一步不能跳。跳過去直接開發，會做出一套「你想像中的診所」而不是「實際運作的診所」。

### 第 1 期：MVP（開幕穩定後啟動，估 2–4 個週末的投入量）

- 診所平面圖 + 分區任務圖示
- 任務模板（含週期自動產生）+ 完成打卡 + 備註交接
- 員工角色卡 + XP 累積 + 經驗條
- 老吳總覽儀表板 + CSV 匯出

### 第 2 期：加值（用順了再說）

- 等級／徽章／技能樹解鎖動畫
- **LINE Bot 通知**（台灣診所最自然的通知管道）——逾期任務提醒、每日晨間任務清單推播
- 任務照片佐證（消毒、環境清潔可拍照存證）
- 角色外觀自訂、月度小結動畫
- 多診所欄位啟用（若展店）

## XP 與獎金怎麼對接（重點設計）

不要另外發明一套點數，**直接接上你已經談定的獎金制度**：

| 現有獎金項目 | 系統怎麼對應 |
|-------------|-------------|
| 全勤 1,500/月 | 出勤由差勤系統認定，本系統僅顯示參考 |
| 久任（滿6月5,000／滿1年一個月薪） | 角色卡顯示「到職天數進度條」，滿條自動提醒 |
| **技能晉升加給 +2,000–3,000/月** | **技能樹解鎖**：包藥 → 消毒 → 掛號結帳 → 衛教 → 針傷輔助／拔針（需公會受訓）。解鎖條件 = 完成該類任務 N 次 + 老吳認證。這是整套系統最有價值的一塊 |
| 服務品質獎金（季 1,000–3,000） | 季內任務完成率 + **主動提報流程改善的次數**（呼應「共創 SOP 遊戲化」，提改善建議也是一種高 XP 任務） |

> 設計原則：**XP 是佐證資料，不是自動發錢的公式。** 最後拍板權在你，系統只負責讓對話有依據。這樣既避免員工「刷任務換錢」，也避免你憑印象決定加薪。
